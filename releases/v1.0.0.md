# v1.0.0

The desktop shell was rebuilt from Tauri 2 + React onto native
[Slint](https://slint.dev), over the unchanged `ephemera-core` logic crate. This is
the first release built from that migration — see
[`migration/PLAN.md`](../migration/PLAN.md) for the full plan and
[`migration/tasks.json`](../migration/tasks.json) for the per-phase execution record.

## Changes

### UI (Slint, replacing Tauri + React)

- Full port of the RAM, Disk, Database, and Cloud panes from
  `src/components/*.tsx` to `crates/ephemera-app/ui/app.slint`.
- 4 Hz dashboard (`Instruments`): RAM store bytes and process RSS as two stacked
  bar-style sparklines sharing one x-axis, never a dual-axis chart. Built as
  `for point in history: Rectangle { ... }` rather than an SVG line chart — Slint
  1.17's `Path` element rejects `for` loops, so a dynamic line chart wasn't viable.
- In-app drag-and-drop between panes via Slint's `DragArea`/`DropArea`.
- The RAM-bypass streaming report (`StreamReport`) is now shown in a modal
  (`StreamModal` in `app.slint`) — the Tauri build measured this data but never
  displayed it; `on_stream_upload_to_disk` was discarding the returned report.
- UI and core now run in one process, one address space — no IPC, no serialization
  boundary. `ShellState` (`model.rs`) projects `ephemera_core::state::AppState`
  directly into Slint properties via direct function calls, marshalled onto the UI
  thread with `slint::invoke_from_event_loop` where needed (the 4 Hz sampler thread
  and the 5s DB/cloud poller).
- `src/` (React) and `src-tauri/` (Tauri host, including its `tests/` integration
  tests, folded into `crates/ephemera-core/tests/`) removed entirely.
  `crates/ephemera-app` is the only UI going forward.

### Fixes found and made while porting

- **Config loading was dropped during the port.** The Tauri build resolved a `.env`
  file and the GCS key path relative to the executable's own directory, walking
  upward through ancestor directories (a real prior fix, commit `0e2fc7a`, needed
  because launching the release binary from anywhere other than its own directory
  silently lost the cloud connection). The Slint port never carried this over —
  `main.rs` read only bare `std::env::var` calls with no config-file support at all.
  Restored via a `find_upwards` helper in `crates/ephemera-app/src/main.rs`, plus a
  `dotenvy` dependency added to `ephemera-app`'s `Cargo.toml` (it had been a dead,
  unused dependency of `ephemera-core` instead).
- **Per-tick heap churn in the dashboard.** `ShellState::push_metrics` rebuilt the
  entire 240-point history `Vec` and wrapped it in a fresh `Rc<VecModel>` on every
  4 Hz tick — reallocating 4 times a second on the very code path measuring the
  app's own memory use. Caught by an independent review during Phase 4. Fixed to a
  persistent `VecModel` held in a `thread_local!` (it's `Rc`-backed and only ever
  touched from the UI thread; `ShellState` itself must stay `Send + Sync` to cross
  into the sampler/poller threads, so the model can't live as a plain field on it)
  and mutated in place via `push`/`remove` instead of rebuilt.
- **Misleading dropzone copy.** The RAM pane's dropzone said "drop files here or
  click to browse," but only the click-to-browse path (`rfd::FileDialog`) is wired.
  Investigated implementing real OS-level file drag-and-drop to match the Tauri
  build's native drop event — not achievable on Slint 1.17: its
  `DataTransfer`/`DropArea` API (`i-slint-core-1.17.1/data_transfer.rs`) carries
  only images, plain text, and same-process payloads, with no file-path concept at
  all. Fixed the copy to "click to browse for files" and documented the constraint
  in code and in `docs/02-architecture.md`, rather than leave a silently broken
  affordance in place. In-app dragging a file between panes is unaffected — that's a
  same-process `DragArea`/`DropArea` payload, not an OS file drop.
- **Refresh button contrast.** The button was the only spot in `app.slint` using
  Slint's generic `std-widgets::Button` instead of the app's own `PaneButton`
  component — on this build's rendering, that produced white text on a light grey
  background against the app's warm cream theme, effectively unreadable. Swapped to
  `PaneButton` to match every other button in the app; the unused `Button` import
  was dropped from the `std-widgets.slint` import line.

### Component/data conflicts resolved during parallel generation

Phase 3 (RAM/Disk/Sink panels) and Phase 5 (drag-and-drop/stream modal) each
generated multiple branches in parallel from the same base, all extending the same
three files (`app.slint`, `main.rs`, `model.rs`). Merged serially, rebasing each
branch onto the previous one's merge, with real git conflicts at every step. One
genuine correctness issue surfaced this way (not just textual conflicts): the sink
panel's own generated branch defined a second, differently-shaped `FileCard`
component (a single `delete-clicked` callback vs. the RAM pane's four action
callbacks) that collided by name with the RAM pane's existing `FileCard`. Renamed to
`SinkFileCard` and harmonized a `formatted-size` field name to the `size-formatted`
convention already established by the other panels.

## CI / pipeline

- `.github/workflows/ci.yml`: replaced the separate frontend (pnpm/vite) and
  backend (Tauri) jobs with two jobs — `core` (fmt/clippy/test for
  `ephemera-core`, no GUI dependencies needed at all) and `app`
  (fmt/clippy/test/release-build for `ephemera-app`, Slint's Linux windowing/
  rendering dependencies instead of WebKitGTK). Verified on a real PR run
  (actions/runs/31502637812) before merging — both jobs passed.
- `.github/workflows/release.yml`: replaced the `tauri-apps/tauri-action`
  bundle-and-publish step with a plain `cargo build --release --target <target>`
  per platform plus `softprops/action-gh-release` to attach the raw binary.
  `prerelease: false` preserved unchanged per project policy. This is the first
  tag to actually exercise the rewritten workflow — all 5 matrix legs (Linux
  x86_64/arm64, Windows x64, macOS arm64/x64) built and published successfully,
  notably including **Linux arm64**, which had failed on every release since
  v0.2.0 under the old Tauri pipeline (undiagnosed at the time — `pnpm tauri build`
  exiting non-zero partway through bundling).
- Migration orchestration tooling (`migration/dispatch.sh`, `pr.sh`, `status.sh`,
  `run_all.sh`, `PLAN.md`, per-task prompts) committed to the repo for the first
  time — it had existed locally, uncommitted, prior to this release.

### Real problems hit in the migration pipeline itself

Worth recording since the pipeline may run again for future work:

- **`opencode --dir` pointed at the main checkout, not the task's isolated
  worktree.** Every "parallel" generate task was actually writing into the same
  directory, racing `git checkout` against each other — root-caused by reading an
  agent's own transcript (`git status` inside its session showed `On branch main`
  when it should have shown the task's own branch). Fixed by passing `--dir "$PWD"`
  (the caller's cwd, set by the wrapping `cd` before invoking the CLI) instead of a
  hardcoded repo path.
- **Worktrees living inside the repo directory tree escaped into an unrelated
  workspace-root `Cargo.toml`** belonging to a separate, untracked
  test-infrastructure effort also present in this checkout. Cargo's manifest
  search walks the filesystem, not git worktree boundaries, so every worktree's
  `cargo test` picked up that outer workspace file and failed with a "package
  believes it's in a workspace when it's not" error. Fixed by relocating all
  migration worktrees outside the repo's directory subtree entirely
  (`~/dev/ephemera-migration-worktrees/`).
- **A no-op generation silently reported "done."** One task's agent spent its
  entire turn budget researching a real blocker (the `Path`/`for`-loop
  constraint above) and never wrote a single file; the dispatch script's test
  gate then trivially passed against completely unchanged code. Fixed by
  failing a generate task outright whenever it produces no commit at all.
- **Two `opencode-go/*` models (`deepseek-v4-flash`, `kimi-k2.7-code`) silently
  exited with no error message, right before their first file write** — twice,
  across two separate tasks. Switching provider to `google/gemini-3.6-flash`
  (also via `opencode`) worked immediately both times; root cause undiagnosed.
- **A review model hallucinated a missing CI toolchain step that was verifiably
  present**, reproducibly, across two independent diffs — directly confirmed via
  `grep` both times. Rather than retry indefinitely against a reproducible
  hallucination, resolved by waiting for the PR's real GitHub Actions run
  instead, which passed cleanly on both jobs — stronger ground truth than either
  LLM review.
- **Generated `target/` build directories got staged and nearly pushed** (one
  branch's diff reached 2645 changed files before being caught and cleaned).
  `dispatch.sh` now force-appends `**/target/` to a worktree's `.gitignore`
  before staging, regardless of what the generated code's own `.gitignore`
  covers.
- **`git add -A` after removing stale `.gitignore` lines nearly staged two real
  secrets** (the old Tauri build's `.env` and GCS service-account key) plus a
  stale Vite build output directory and the entire `node_modules/` tree — all
  caught and unstaged before the retirement commit; none were ever committed.

## Known gaps

- **Vault path does not persist across restarts.** A documented requirement
  (`docs/01-requirements.md` line 182: "MUST persist the vault path between
  runs"), but confirmed **pre-existing** — `ephemera_core::set_vault_path` was
  always in-memory-only, even in the original Tauri build, predating this
  migration entirely. Left as-is rather than adding new behavior the Tauri build
  never had; worth its own task and its own review.
- **Spanish/English toggle not re-implemented.** The Tauri build's i18n
  (`src/lib/i18n.ts`, a Zustand-persisted toggle) was removed along with `src/`.
  Slint has its own `@tr()` translation mechanism; unstarted.
- **`release.yml`'s matrix build was unverified until this tag** — now confirmed
  working across all 5 platforms by this release itself.
- **No pixel-level visual verification against the old Tauri screenshots.** No
  Wayland screenshot tool (`grim`, `slurp`, `gnome-screenshot`) was available in
  the build environment, and ImageMagick's `import` requires X11, unavailable on
  this Wayland-only session. The release binary was confirmed to launch and run
  its 4 Hz sampler with no errors or panics in its log output, but layout was not
  visually diffed pixel-for-pixel against the previous build.
- **Dark mode not implemented in the Slint UI.** The Tauri build's CSS-variable
  approach doesn't carry over directly; needs a Slint-native design.
- **`upload_to_ram` still takes a single path** — multi-file batch quota
  validation (spec: validate the whole batch against remaining quota as a
  whole) is unimplemented, unchanged from the original Tauri build.
- **A separate, untracked local effort's root `Cargo.toml`** (present on the
  machine this release was built on, not part of this repo's git history) now
  references the deleted `src-tauri/` as a workspace member and will error on
  `cargo` commands run from the repo root on that machine specifically, until
  reconciled by that effort. Does not affect a fresh clone of this repository.

## Technical details

**Memory measurement.** Full-app idle RSS was measured by launching both a release
build of this Slint app and a fresh build of the pre-migration Tauri app (checked
out at commit `03e62d0`) under identical conditions, reading `VmRSS` from
`/proc/<pid>/status` (and summing the process tree for Tauri's WebKitGTK children).
Result: 126,084 kB (Slint, single process) vs. 179,544 kB main-process / 401,935 kB
tree (Tauri, 3 processes) — a 3.2x reduction counting the full tree, 30% counting
main process alone. The Tauri children (`WebKitNetworkProcess` + `WebKitWebProcess`)
alone accounted for ~222 MB, more than the entire Slint app's footprint. Workload
deltas (RAM upload, disk persist, DB save) were measured via a standalone harness
against `ephemera-core` directly, since neither app accepts CLI-driven file loading
and no Wayland UI automation tooling was available to drive the GUI itself. Full
methodology, harness source, and raw numbers:
[`migration/outputs/P6-T1/REPORT.md`](../migration/outputs/P6-T1/REPORT.md).

**Test coverage at release time.** 22 unit/integration tests in `ephemera-core`
(including live round-trips against a real Postgres container and the real GCS
bucket `gs://ephemera-vault-alterna`), 8 unit tests in `ephemera-app`. All passing
on `main` at the tagged commit.

**Versioning.** `crates/ephemera-app/Cargo.toml` and `crates/ephemera-core/Cargo.toml`
bumped together to `1.0.0`; both crates' `Cargo.lock`s regenerated via `cargo check`.
